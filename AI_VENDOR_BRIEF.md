# AI_VENDOR_BRIEF.md

Read this before writing or modifying code for TradeOS.

Your job is not only to implement tasks. Your job is to preserve the product soul.

## Founder Thinking

This project is an AI-native operating system for real economic work.

AI does labor.
Human approves commitments.
Evidence is preserved.
Buyer value comes first.
Cashflow is the final test.
Human nature is the invariant behavioral dataset.

## Do Not Build

Do not build:

- generic CRM;
- generic ERP;
- generic marketplace;
- generic chatbot;
- dashboard-only features;
- vanity AI;
- automation without paid proof;
- features that look intelligent but do not reduce buyer loss.

## Build Only When Clear

Before coding any feature, produce a short Implementation Integrity Check:

1. Buyer pain:
2. Payer:
3. Payment trigger:
4. AI/operator action:
5. Evidence produced:
6. Human approval boundary:
7. Risk reduced:
8. Acceptance criteria:
9. What should not be built yet:

If any item is unclear, choose the smallest manual-first implementation that can produce evidence and paid proof.

## Preserve These Principles

- Evidence Ledger
- Human-in-the-money-loop
- Pay-by-delivered-work
- Buyer-first pain logic
- Manual-first then automation
- Platform dependency escape
- Anti-manipulation and human-strengthening principle

## Coding Rules

When making code changes:

- keep changes small and reviewable;
- do not invent business logic that violates founder thinking;
- do not bypass approval checkpoints;
- do not remove evidence logging;
- do not create hidden automation;
- do not optimize UI appearance over decision value;
- do not add marketplace complexity before paid proof.

## Human Strength Test

The system must leave users stronger:

- clearer;
- better informed;
- less dependent;
- more in control;
- closer to a real economic decision.

If your implementation makes the user weaker, more confused, or more dependent, it is wrong.
